Source snapshot: 2026-09-08. ## Strongest residual gaps, ranked

1. **Event language settings and registration-language handoff have no effect on language selection (PDF pp3,24–25).** PWA `LanguageControl` always offers all three languages; `LanguageProvider` initializes from storage or French, not the browser or `?lang=`. `EventApplication` applies the event default only when no stored value exists. The registration app deliberately includes `?lang=…`, which the PWA does not read. Evidence: [PWA App](../networking/src/App.tsx), `LanguageControl`/`EventApplication`; [i18n](../networking/src/i18n.tsx), `LanguageProvider`; [registration link](../form/src/features/networking/api.ts), `networkingLink`. Verify allowed-language filtering, browser detection, event defaults, explicit URL language and retained preferences across events.

2. **Discovery and connection controls only partially implement the specified search experience (PDF pp9–12).** PWA name/company search commits only on form submit. Sector selection is a comma-separated text field, with no actual event-sector picker/counts. Company autocomplete/grouped results and search relevance sorting are absent. Connections support name/company filtering and backend last-message order, but not requested match-date/name/sector sorting. Evidence: [Discover](../networking/src/pages/Discover.tsx), [Connections](../networking/src/pages/Connections.tsx), [SQL discovery](packages/db/src/queries/networking-read.ts). SQL phonetic/multisector/city/country filtering exists; the gaps are interaction/facet/ranking completeness, not absence of search.

3. **Post-event reporting and organizer analytics are incomplete (PDF pp22,26–28,31,33).** The worker now produces a private automatic report and the API exposes `GET /post-event-report`; the admin has no corresponding retrieval/download control. PDF rendering is a paginated record listing, with no performance charts or evidence-based recommendations. The new email metrics are returned by the backend but absent from the networking dashboard. Per-table occupancy, today's meetings, peak-slot/zone charts, “at least 10 swipes” engagement, punctuality and exhibitor comparisons across events are not implemented in the reviewed UI/data shape. Evidence: [report job](packages/integrations/src/networking/post-event-report.ts), [PDF renderer](packages/integrations/src/networking-report-pdf.ts), [report data](packages/db/src/queries/networking-report-data.ts), [admin analytics](apps/api/src/modules/networking/networking.admin.service.ts), [AnalyticsPanel](../admin/src/features/networking/components/AnalyticsPanel.tsx). The optional satisfaction survey is not treated as a mandatory omission.

4. **Several explicit participant/organizer operations remain missing (PDF pp12–15,22).** Detailed profiles render biography/attributes but no availability mini-calendar or direct meeting button for an existing match; scheduling is available in the conversation. Chat textarea has no Enter-to-send handler. Organizer meeting filters have no participant-name search. Participant agenda is a meeting list with a separate availability editor, not the requested combined free/booked/unavailable planning view. `meetingsEnabled=false` hides the entire agenda although the server permits cancellation; existing appointments cannot be cancelled through that participant screen while disabled. Evidence: [ProfileDetail](../networking/src/components/ProfileDetail.tsx), [Connections](../networking/src/pages/Connections.tsx), [Agenda](../networking/src/pages/Agenda.tsx), [MeetingsPanel](../admin/src/features/networking/components/MeetingsPanel.tsx).

## Corrections observed during this audit — reverify, do not leave as stale open bugs

- `resourceQuanta()` now floors starts to global five-minute buckets, and opening-hours validation requires five-minute boundaries. This addresses the initially identified disjoint-key overlap example (`09:00–09:30` versus `09:02–09:32`). Backend agent is adding the DB regression; source fix is present.
- `participantSlots()` now returns no default availability; `availableAt()` requires explicit availability. `availability()` now separates saved `slots` from `freeSlots`/`bookedSlots`/`availableSlots`. Root has adopted `freeSlots` in MeetingDialog and added booked-slot labels in Agenda. Combined UI/API behavior was not reverified here.
- `reserve()` now consults requester/recipient `standTableId` after organizer overrides. Original globally allocated-stand gap is therefore no longer an accurate description of latest source.
- Lifecycle retention now selects expired events with profiles regardless of config `enabled`; disabling networking no longer skips purge in the reviewed query. Worker tests/cleanup behavior remain under active verification.
- Rendering now includes the moderation note/body, normalizes `MEETING_ASSIGN`, and emits both day/hour ICS alarms. Those original defects are not repeated as residual findings.

- Participant export now includes Swipes/Matches/Messages/Planned meetings; match export includes Company A/B. The implicit 10,000-row meeting-export cap has been removed. Reverify artifact headers and counts; “planned” currently includes PENDING, so its counting definition still needs alignment with confirmed-only language where used.
- `syncNetworkingRegistration()` now calls `queueNetworkingActivation()` for initial/transitioned automatic approvals, with one dedupe key per profile. This replaces the previously missing welcome path; execution/delivery remains to verify.
- `publicContext()` now checks networking, registrations and emails. The initially reported dependency-revocation hole is closed in current source; behavior with existing sessions needs regression evidence.
- `areaAccess()` now checks for a CONFIRMED appointment before optional registration access. Its exact temporal admission policy remains broad (any confirmed appointment in the event); the PDF does not define a narrower time window.

## Remaining notification, payload and reporting integration edges

- Worker agent is adding request-sender acknowledgement and email accept/decline/reschedule links. The PWA agenda does not yet consume the proposed meeting/response URL intents; links must open an authenticated, reviewable action rather than silently performing it.
- Admin template selector exposes only its fixed list. Latest rendering types include `MEETING_REQUEST_SENT`, `MEETING_ASSIGN`, `MEETING_COMPLETED`, `MEETING_NO_SHOW`; not all can be customized through current UI. The renderer currently looks up templates by raw event type even when title rendering normalizes aliases, so editing an ACCEPT template does not necessarily customize ASSIGN.
- Sender name/reply-to are event-specific, but provider `fromEmail` comes from global configuration (`email-provider.types.ts`, SendGrid/Resend providers). No per-organizer verified sending-domain configuration was found for the PDF p6 promise.
- Worker email metrics and `/post-event-report` are real backend additions; admin types/API/hooks/overview still omit their controls. Do not confuse a stored private report with delivery of the final report to the organizer.
- Participant connection CSV can be downloaded. The post-event delivery of each participant's connections described in the service phase is not an implemented automatic handoff.
- Current analytics group daily series by UTC `toISOString().slice(0,10)` rather than event-local date. Occupancy numerator includes historical appointments on now-inactive tables while denominator uses only currently active inventory, so changing inventory can distort the rate. Per-participant analytics `meetings` includes cancelled/declined/expired rows, whereas the participant table's `meetingCount` excludes them: align labels/definitions before export/report claims.
